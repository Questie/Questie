  - Checkout: `/home/logon/projects/Questie-clones/Questie-Forever` (the main working tree).

Both checkouts belong to one repository, so every ref works from either directory.

## Verified overlap findings

`WP` is `origin/waypoints` and `B` is `blob`. Line numbers are approximate, so check them before relying on them.

1. **`IsLineFrame` is gone.** `B Polygon/QuestiePolygon.lua:~1000` (`isCursorOnMap`) calls `QuestieFramePool.IsLineFrame(focus)`, defined at `B QuestieFramePool.lua:~152-159`.
   - WP deletes that function. WP's paths are not mouse-enabled, and WP's own check is `focus == WorldMapFrame.ScrollContainer` (`WP WaypointMap.lua:~127-129`).
   - In the combined code this is a nil call every frame the cursor is over any icon or pin.
   - `B QuestiePolygon.test.lua:~105,174,185` stubs `IsLineFrame`, so the tests stay green.
2. **`DrawWaypoints` signature.**
   - WP: `QuestieMap:DrawWaypoints(icon, entity, waypoints, zone, hostile)` at `WP QuestieMap.lua:~728`. Callers are `WP QuestieMap.lua:447,513`, `AvailableQuests.lua:838`, `QuestFinisher.lua:146` and `QuestieQuest.lua:1343`.
   - B keeps the old `(icon, waypoints, zone, color)` form at `B QuestieMap.lua:~745`, built on `CreateWaypoints` and `DrawLineIcon`. B's callers are `B QuestieMap.lua:455,521` and `B QuestieQuest.lua:~1395`. The last is inside `_DrawObjectiveWaypoints` and passes a hardcoded hostile color `{1, 0.2, 0, 0.7}`.
3. **Leftover line model.** WP has zero references to `lineFrames`, `CreateWaypoints`, `DrawLineIcon` or `zoneWaypoint(Hover)ColorOverrides`. B still has `lineFrames` in:
   - `QuestieFrame.lua` (12)
   - `QuestieFramePool.lua` (6)
   - `TrackerUtils.lua` (6)
   - `QuestieMap.lua` (2)
   - `QuestieQuest.lua` (1)
   - `MapIconTooltip.lua` (1, together with `zoneWaypointHoverColorOverrides` at `~109-113`)
   - `QuestieFrame.test.lua` (1)
   
   WP replaced all of these with `QuestieWaypoints.*` (for example `SetHighlighted`, `RemoveOwner` and `OwnerChanged`).
4. **`minimapTwin` never set for fallback markers.** `WP QuestieMap.lua:~592,690` sets `icon.minimapTwin`, which `WP QuestieWaypoints.lua:~137,150` and `WaypointMinimap.lua:~309` use.
   - B's `DrawWorldIcon(data, areaID, x, y, phase, showFlag, destination)` (`B QuestieMap.lua:~648-712`) can draw the map and minimap icons separately.
   - B's blob-mode fallback markers (`B QuestieQuest.lua:~1373-1377`) call it twice, so the twin link is never made.
5. **Fallback copy shares paths.** `B QuestieQuest.lua:~1344` `_FallbackIconData` shallow-copies icon data except `lineFrames`. In the combined code it would therefore share WP's `data.waypointPaths`, which WP deliberately shares across icons with the same data (`WP QuestieWaypoints.lua:~67-68`, `QuestieFrame.lua:~38`).
6. **`MapIconTooltip` generalized twice.**
   - WP: `ShowOnTooltip(self, Tooltip, owner, icons)` (`WP MapIconTooltip.lua:~79`). `Show` calls `WaypointHover.End(self)` first (`~65-68`). The alpha exemption is `alpha == 0 and not owner`. Callers are `WP WaypointHover.lua:~50` (its own minimap tooltip frame) and `GamepadMapHover.lua:~101`.
   - B: `ShowOnTooltip(self, Tooltip)` (`B :~73`) calls `QuestiePolygon.EnterMarker(self)` for polygon markers. Its throttle adds `Tooltip:IsOwned(self)`. It delegates to `ShowForIcons(owner, icons, Tooltip, objectivePrefix)` (`B :~185`), and `Release(owner, Tooltip)` sits at `B :~505`. The caller is `B QuestiePolygon.lua:~368`.
7. **Tooltip tug-of-war.**
   - `B QuestiePolygon.lua:~341-372` `_UpdateAreaTooltip` takes GameTooltip back whenever the mouse focus is `ScrollContainer` and the tooltip isn't already owned by it.
   - WP's `WaypointHover` `_Enter` calls the icon's `OnEnter`, so the icon owns GameTooltip. Its `_Leave` (`WP WaypointHover.lua:~80-100`) clears `GameTooltip._Rebuild` and `ShownAsMapIcon` whenever another frame owns the tooltip.
   - Over a path that crosses an area, the two fight over the tooltip. `B Polygon/README.md:~13` says waypoint lines keep their own tooltips, which is wrong once combined.
8. **Duplicated minimap layer.**
   - `WP WaypointMinimap.lua`: projection `~56-66`; `_IsAtlas`, `ShapeMask` and `_ApplyShapeMask` `~117-147`; `SetMaskTexture` post-hook `~153-162`; `_IsSecret` `~191-198`; per-frame player/view reads `~347-355`; root, container, masks and OnUpdate `~427-461`.
   - `B PolygonMinimap.lua` has the same pieces at `~82-97`, `~132-160`, `~167-176`, `~260-266`, `~283-292` and `~351-384`.
   - They disagree on `CORNER-*` minimap shapes: WP uses the round mask (test `WP WaypointMinimap.test.lua:~430-437`) and B uses the square one (test `B PolygonMinimap.test.lua:~322-328`).
   - Both roots sit at `Minimap` frame level + 1, so their draw order depends on load order.
9. **Duplicate asset.** `WP Icons/minimap-player-mask.tga` is byte-identical to `B Icons/polygon-minimap-player-mask.tga`. `B PolygonMinimap.lua:~45` hardcodes `Interface\Addons\Questie\...` instead of using `QuestieLib.AddonPath`.
10. **HereBeDragons-Pins.** Both branches add an identical `pins:GetMinimapView`. B also bumps `MINOR` 16→17, adds an `oldversion < 17` upgrade, and adds world-map pin hooks.
11. **Migration.** Both branches add migration `[42]`. WP's writes `waypoint*` profile keys; B's sets `enableQuestiePolygons` if it is nil. B's becomes `[43]`, and the tests assert `migrationVersion`.
    - **Update, waypoints `f567796eb`:** master added `[42]` (`enableTooltipsSpellID`), and WP's is now `[43]`. B's becomes **`[44]`**. See README M1.
12. **B tests for the deleted model.**
    - `QuestieFrame.test.lua` `~196-206` (`ResetHoverHighlights` with `lineFrames`)
    - `QuestieFramePool.test.lua` (`CreateLine`/`IsLineFrame` at `~61-69`, motion propagation at `~102-122`)
    - the `QuestiePolygon.test.lua` stubs
13. **Moot combat fix.** B's motion-propagation fix in `QuestieFramePool` (`linesAwaitingMotion`, `motionDriver`) has nothing to do once combined, because WP paths are not mouse-enabled.

**Minor findings:**
- **Two world-map hover pollers:** `WP WaypointMap.lua:~178-182` (`_Update`, `_UpdateHover`) and `B PolygonRenderer.lua:~193-236` (`hoverDriver`).
- **Duplicate geometry helpers:** `_IsFinite` exists three times (`WP WaypointGeometry.lua:~33`, `B PolygonGeometry.lua:~47`, `B PolygonNudging.lua:~18`). Segment distance also exists three times (`WP WaypointGeometry.lua:~364`, `B PolygonGeometry.lua:~254`, and inline in WP `Trim` at `~333-345`). `worldBounds` is an array in WP and named fields in B.
- **Scheduling:** WP redraws synchronously inside OnUpdate, costing about 80 ms total for all Classic patrols (`WP docs/waypoints.md:~173`). B uses a coroutine `Checkpoint` frame budget (`B PolygonGeometry.lua:~84-99`), plus a separate yield every 30 markers at `B QuestiePolygon.lua:~1048`.
- **Shift redraw:** it doesn't reach WP's separate `QuestieWaypointMinimapTooltip`.
- **Route highlight on polygon markers (unverified):** hovering a polygon marker or cluster may not highlight routes, because `WaypointHover` hooks the icon's own `OnEnter`.
- **Option wording:** WP's "minimap icons must be enabled" doesn't cover blob mode's cluster markers.

## What David wants from each plan

Study both implementations deeply and compare them. Then design the best, most future-proof solution. That may mean taking one side, taking the other, or combining them into something more modular that covers the function better.

David's taste:
- Build complex things as simply as possible. YAGNI, and no speculative abstraction.
- Deep modules with small interfaces.
- Type safety through LuaCATS annotations.
- Focused tests, not happy-path busywork.
- Comments that stay in sync with the code.

Repo conventions are in `AGENTS.md` at the repo root. Read it first. Among other things it says to prefer a new focused module over growing an existing one, to add new modules to all TOCs, and to prefer plain functions over methods.

## Plan template (use these headings)

1. **Problem**: what each branch does today (file:line per branch), where they collide, and what breaks.
2. **Comparison**: strengths and weaknesses of each implementation, and what to keep from each.
3. **Target design**: modules and ownership; public API with LuaCATS signatures; data flow; invariants. Explain why it holds up for the future without overbuilding. Briefly list the alternatives you rejected and why.
4. **Sequencing**:
   - (a) The minimal changes needed during the rebase, so every replayed blob commit still loads and passes tests. Name the blob commits, by subject, whose conflict resolution must make each change.
   - (b) Follow-up commits after stacking, each with a Conventional Commit title and its exact file-level changes.
5. **Tests**: tests to add, change or delete, and what each one proves. Follow the AGENTS.md conventions.
6. **Docs and comments**: what to update (`docs/waypoints.md`, `Polygon/README.md`, inline comments and so on).
7. **Verification**: targeted `busted` commands, luacheck, and specific in-game checks for David (client, zone or quest, what to look for).
8. **Risks and open questions**: each with your recommendation.
9. **Contracts with other areas**: what you assume from the other areas and what you provide to them.
